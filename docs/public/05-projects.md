# Projects — The Coordinated Intervention

**Symbol:** ◆
**Question:** _What interventions do we commit to?_
**Definition:** A temporary coordination construct that organizes intentional work toward a bounded outcome through coordinated intervention.

A project is where belief meets commitment. It is the organizational container for _doing something about_ the desired state — a time-bounded, narrative-heavy construct that bridges the gap between objectives and executable tasks.

## The Doctrine of Boundedness

Alissa enforces a strict principle: **if it has no timeline, it is not a project.** Every project requires an `endDate`. An unbounded intervention is indistinguishable from the status quo.

## The Narrative: Structured Intent

Every project carries a **Project Narrative** — a structured document articulating the intervention intent:

| Section | Question It Answers |
|---|---|
| **Context** | What is the current situation? |
| **Problem / Opportunity** | What condition needs to change? |
| **Desired Change** | What should be different when this succeeds? |
| **Intervention Intent** | What, broadly, do we plan to do? |
| **Known Constraints** | What boundaries limit our options? |
| **Open Unknowns** | What do we not yet know that might matter? |

## Strategic Alignment

Projects are explicitly linked to the layers beneath them:

- **Objective Alignment** — Which objectives does this project serve?
- **Causal Alignment** — Which theories of change underpin this intervention?

These alignments form the traceability chain from execution back to belief.

## The Outcome Oneliner

Every project requires an `outcomeOneliner` — a single sentence answering: _"What condition should exist if this intervention succeeds?"_

## The Accountability Model

Every project has three key roles:

| Role | Responsibility |
|---|---|
| **Owner** | Accountable for delivery of the intervention |
| **Reporter** | Surfaced the need; defaults to owner on creation |
| **Sponsor** | Underwrites AI costs; cascades to milestone tasks |
